# Πρόγραμμα ξενοδοχείου

Εφαρμογή διαχείρισης ξενοδοχείου, ανεξάρτητη από το ITSUPP, με δική της βάση Supabase.

## Τι κάνει

**Προσωπικό** (`index.html`, εγκαθίσταται και στο κινητό)
- **Σήμερα**: αφίξεις, αναχωρήσεις, ποιοι μένουν τώρα, πληρότητα, online αιτήματα προς επιβεβαίωση, όσοι έπρεπε να έχουν φύγει.
- **Ημερολόγιο**: δωμάτια × ημέρες με τις κρατήσεις. Πάτημα σε κενό κελί → νέα κράτηση σε αυτό το δωμάτιο/ημέρα.
- **Κρατήσεις**: λίστα με αναζήτηση και φίλτρα, χρέωση/πληρωμένα/υπόλοιπο, πηγή (Booking, Airbnb κ.λπ.).
- **Check-in / Check-out**: ανάθεση δωματίου, στοιχεία ταυτότητας/διαβατηρίου, προειδοποίηση για υπόλοιπο ή μη καθαρό δωμάτιο. Μετά το check-out το δωμάτιο γίνεται αυτόματα «Βρώμικο».
- **Πελάτες**: καρτέλα πελάτη με ιστορικό κρατήσεων.
- **Καθαριότητα**: κατάσταση κάθε δωματίου (Καθαρό / Βρώμικο / Για έλεγχο / Εκτός λειτουργίας), αφίξεις/αναχωρήσεις ημέρας, σημειώσεις. Οι καμαριέρες **δεν** βλέπουν στοιχεία πελατών.
- **Δωμάτια, Χρήστες, Ρυθμίσεις** (μόνο διαχειριστής).

**Πελάτες** (`book.html`, ελληνικά & αγγλικά)
- Αναζήτηση διαθεσιμότητας και αίτημα κράτησης (μπαίνει ως «Εκκρεμεί» μέχρι να το επιβεβαιώσει η ρεσεψιόν).
- «Η κράτησή μου» με κωδικό κράτησης + email.
- Online check-in: ο πελάτης συμπληρώνει έγγραφο ταυτότητας κ.λπ. πριν φτάσει.

**Tablet δωματίου** (`tablet.html`, ελληνικά & αγγλικά)
- Αρχική με καλωσόρισμα (με το όνομα του πελάτη που έχει κάνει check-in), Wi‑Fi, ώρα check-out, τηλέφωνο ρεσεψιόν.
- Πληροφορίες ξενοδοχείου (πρωινό, πισίνα, παραλίες κ.λπ.) που γράφει ο διαχειριστής.
- Υπηρεσίες: Transfer, Yachting, εκδρομές, spa, εστιατόριο κ.ά. Ο πελάτης στέλνει αίτημα (ημερομηνία, ώρα, άτομα, για transfer διαδρομή και αριθμό πτήσης/πλοίου).
- «Τα αιτήματά μου»: κατάσταση κάθε αιτήματος και ακύρωση όσο δεν έχει επιβεβαιωθεί.
- Αιτήματα γίνονται μόνο όταν υπάρχει πελάτης με check-in στο δωμάτιο. Ο επόμενος πελάτης δεν βλέπει τα αιτήματα του προηγούμενου.
- Μετά από 2 λεπτά αδράνειας επιστρέφει στην αρχική.

Στην εφαρμογή προσωπικού:
- **Αιτήματα**: η ρεσεψιόν βλέπει τα αιτήματα από τα δωμάτια, τα επιβεβαιώνει, ορίζει τιμή και τα κλείνει. Νέο αίτημα εμφανίζει ειδοποίηση και αριθμό στο μενού (έλεγχος κάθε 30″).
- **Tablet** (διαχειριστής): μήνυμα καλωσορίσματος, Wi‑Fi, φωτογραφία, ενότητες πληροφοριών, υπηρεσίες με τιμές, και σύνδεση συσκευών.

### Σύνδεση tablet σε δωμάτιο
1. Στο tablet άνοιξε `https://<διεύθυνση>/tablet.html` και, ιδανικά, «Προσθήκη στην αρχική οθόνη» για να ανοίγει σε πλήρη οθόνη.
2. Στην εφαρμογή: **Tablet → Συσκευές → Κωδικός σύνδεσης** στο δωμάτιο.
3. Πληκτρολόγησε τον κωδικό στο tablet (ισχύει 15 λεπτά). Το tablet μένει συνδεδεμένο με το δωμάτιο. Με «Αποσύνδεση» ακυρώνεται αμέσως.

Για κανονική χρήση σε δωμάτια, βάλε τα tablet σε λειτουργία kiosk (Android: «Καρφίτσωμα εφαρμογής», iPad: «Καθοδηγούμενη πρόσβαση»), ώστε ο πελάτης να μη βγαίνει από την εφαρμογή.

Η βάση δεν επιτρέπει ποτέ δύο κρατήσεις στο ίδιο δωμάτιο τις ίδιες νύχτες.

## Channel manager (Booking.com, Airbnb, Expedia…)

Σύνδεση μέσω **[Channex.io](https://channex.io)**, ενότητα **Κανάλια** (διαχειριστής).

- **Εισερχόμενα:** νέες κρατήσεις, αλλαγές και ακυρώσεις από τις πλατφόρμες μπαίνουν αυτόματα, με πελάτη, ημερομηνίες, άτομα, ποσό, πηγή (Booking/Airbnb/Expedia) και κωδικό της πλατφόρμας. Η ίδια κράτηση δεν διπλοεισάγεται. Κράτηση πολλών δωματίων γίνεται ξεχωριστές κρατήσεις ανά δωμάτιο.
- **Εξερχόμενα:** κάθε κράτηση, αλλαγή ή ακύρωση εδώ (και δωμάτιο «Εκτός λειτουργίας») στέλνει τη νέα διαθεσιμότητα ανά τύπο δωματίου στο Channex, και από εκεί στις πλατφόρμες.
- **Πότε:** κάθε 2 λεπτά αυτόματα (pg_cron) και αμέσως με webhook. Η επιβεβαίωση λήψης (ack) προς το Channex γίνεται μόνο αφού αποθηκευτεί η κράτηση. Αν κάτι αποτύχει, ξαναδοκιμάζεται στον επόμενο συγχρονισμό και φαίνεται στο «Ιστορικό».
- Οι τιμές και οι περιορισμοί (min stay κ.λπ.) ρυθμίζονται στο Channex.

### Βήματα σύνδεσης
1. Λογαριασμός στο Channex. Για δοκιμές: [staging.channex.io](https://staging.channex.io). Δημιούργησε Property και Room Types (π.χ. «Double», «Suite») με τον ίδιο αριθμό δωματίων που έχεις εδώ.
2. Channex → Profile → **API Keys** → νέο κλειδί.
3. Εδώ: **Κανάλια** → Περιβάλλον, κλειδί API, Property ID → Αποθήκευση → **Έλεγχος σύνδεσης**.
4. **Αντιστοίχιση τύπων δωματίων** (εμφανίζονται σε λίστα μετά τον έλεγχο) → Αποθήκευση.
5. Τσέκαρε «Ενεργός αυτόματος συγχρονισμός» → Αποθήκευση → **Πλήρης αποστολή διαθεσιμότητας**.
6. Channex → Webhooks → νέο webhook, event «booking», με τον σύνδεσμο που δείχνει η σελίδα.
7. Στο Channex σύνδεσε τα κανάλια (Booking.com, Airbnb…). Κάνε μια δοκιμαστική κράτηση και δες τη στο «Ιστορικό» και στο «Σήμερα».

Για να προστεθεί άλλος channel manager (Beds24, SiteMinder κ.λπ.) αρκεί νέος «προσαρμογέας» στη `supabase/functions/channel-sync`. Η βάση (ουρά διαθεσιμότητας, εισαγωγή, ιστορικό) είναι κοινή.

## Ρόλοι

| Ρόλος | Πρόσβαση |
|---|---|
| Διαχειριστής | Όλα |
| Ρεσεψιόν | Σήμερα, ημερολόγιο, κρατήσεις, αιτήματα, πελάτες, καθαριότητα |
| Καθαριότητα | Μόνο καθαριότητα (χωρίς στοιχεία πελατών) |

Ο **πρώτος** λογαριασμός που δημιουργείται γίνεται διαχειριστής. Οι επόμενοι εμφανίζονται στο «Χρήστες» και περιμένουν να τους δοθεί ρόλος.

## Εγκατάσταση από την αρχή

Χρειάζονται τρεις δωρεάν λογαριασμοί: **Supabase** (βάση), **GitHub** (κώδικας), **Vercel** (δημοσίευση). Χρόνος: περίπου 20 λεπτά.

### 1. Supabase: βάση δεδομένων
1. [supabase.com](https://supabase.com) → **New project**. Όνομα π.χ. `hotel`, περιοχή **Central EU (Frankfurt)**. Κράτα τον κωδικό της βάσης σε ασφαλές σημείο.
2. Όταν ετοιμαστεί: **SQL Editor → New query** → άνοιξε το αρχείο `supabase/setup.sql`, αντέγραψέ το **ολόκληρο**, επικόλλησέ το → **Run**. Πρέπει να τελειώσει χωρίς κόκκινο σφάλμα.
3. **Edge Functions → Deploy a new function → Via Editor**:
   - Όνομα: `channel-sync` (ακριβώς έτσι)
   - Σβήσε το παράδειγμα και επικόλλησε το `supabase/functions/channel-sync/index.ts` → **Deploy**.
   - Στις ρυθμίσεις της function **απενεργοποίησε** το «Verify JWT» / «Enforce JWT verification». Η function κάνει μόνη της τον έλεγχο πρόσβασης.
   (Χρειάζεται μόνο για τον channel manager. Αν δεν τον χρησιμοποιείς ακόμη, μπορείς να το αφήσεις για αργότερα.)
4. **Project Settings → API** (ή το κουμπί **Connect**): κράτα το **Project URL** και το **anon public** κλειδί (ή το «publishable»). **Όχι** το service_role / secret.
5. **Authentication → Sign In / Providers → Email**: άφησε ενεργό το «Confirm email». Στο **Authentication → Settings / Attack Protection** άνοιξε το «Leaked password protection».

### 2. Ρύθμιση κώδικα
Άνοιξε το `js/config.js` και βάλε τα δύο στοιχεία του βήματος 1.4:
```js
window.HOTEL_CONFIG = {
  url: "https://xxxxxxxxxxxx.supabase.co",
  key: "eyJ…  ή  sb_publishable_…"
};
```

### 3. GitHub: κώδικας
1. [github.com](https://github.com) → **New repository** → όνομα `hotel` → **Create**.
2. **uploading an existing file** → σύρε **όλα τα περιεχόμενα** του φακέλου (όχι το ZIP, και κράτα τους φακέλους `css`, `js`, `icons`, `supabase` όπως είναι) → **Commit changes**.

### 4. Vercel: δημοσίευση
1. [vercel.com](https://vercel.com) → σύνδεση με GitHub → **Add New → Project** → **Import** το `hotel`.
2. Framework Preset: **Other**. Build/Output: άδεια → **Deploy**.
3. Κράτα τη διεύθυνση (π.χ. `https://hotel-xxxx.vercel.app`, ή σύνδεσε δικό σου domain από Settings → Domains).
4. Πίσω στο Supabase: **Authentication → URL Configuration**:
   - **Site URL**: η διεύθυνση του Vercel
   - **Redirect URLs** → Add: η ίδια διεύθυνση με `/**` στο τέλος (π.χ. `https://hotel-xxxx.vercel.app/**`)

Κάθε αλλαγή που ανεβαίνει στο GitHub δημοσιεύεται αυτόματα από το Vercel.

### 5. Πρώτη χρήση
1. Άνοιξε τη διεύθυνση → **Νέος λογαριασμός** → επιβεβαίωσε το email. Ο **πρώτος** λογαριασμός γίνεται διαχειριστής.
2. **Ρυθμίσεις**: όνομα, διεύθυνση, τηλέφωνο, ώρες check-in/out.
3. **Δωμάτια**: τύποι δωματίων (με τιμή/νύχτα) και δωμάτια («+ Πολλά μαζί» για π.χ. 101–110).
4. **Tablet**: καλωσόρισμα, Wi‑Fi, πληροφορίες, υπηρεσίες με τιμές. Μετά σύνδεση κάθε tablet με κωδικό.
5. **Χρήστες**: δώσε ρόλο στους συναδέλφους μόλις φτιάξουν λογαριασμό.
6. **Κανάλια**: όταν έχεις λογαριασμό Channex (δες παρακάτω).

Διευθύνσεις:
- `/`: εφαρμογή προσωπικού
- `/book.html`: σελίδα κρατήσεων/online check-in για πελάτες
- `/tablet.html`: tablet δωματίων

## Αρχεία

- `index.html`, `js/staff.js`: εφαρμογή προσωπικού
- `book.html`, `js/guest.js`: σελίδα πελατών
- `tablet.html`, `js/tablet.js`, `css/tablet.css`: tablet δωματίου
- `js/common.js`, `css/app.css`: κοινά
- `js/config.js`: διεύθυνση και δημόσιο κλειδί Supabase (**το μόνο αρχείο που αλλάζεις**)
- `supabase/setup.sql`: όλη η βάση σε ένα αρχείο, για νέο έργο
- `supabase/migrations/`: η ίδια δομή, χωρισμένη ανά αλλαγή (ιστορικό)
- `supabase/functions/channel-sync/`: συγχρονισμός με τον channel manager (Edge Function)
